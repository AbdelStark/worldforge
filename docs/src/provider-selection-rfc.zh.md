# 下一批提供方选型 RFC

本 RFC 记录了下一批实现任务的提供方选型决策。它仅是一份规划工件：不会改变提供方目录、生成的提供方文档、README 或公共能力声明。

决策日期：2026-04-30。

当前批次说明：本 RFC 记录的是上一批扩展任务。#130 活跃议题批次的决策已记录在
[提供方批次选型记录](./provider-cohort-selection.md)中。

## 选型规则

在创建实现议题之前，请使用[提供方优先级评估标准](./provider-platform-roadmap.md#provider-prioritization-rubric)。
只有满足以下条件的提供方，才适合作为下一个候选者：

- 具有可映射到某一 WorldForge 能力的稳定可调用接口；
- 针对成功和失败场景具有可安全检出的夹具策略；
- 具有已保留证据的已准备好宿主冒烟测试路径；
- 具有明确的运行时归属权、许可证和维护预期；
- 不需要在基础包中新增依赖。

提供方名称本身不是扩展目录的理由。选定的批次应改善真实的可调用行为，或解锁具体的宿主工作流。

### JEPA-WMS 议题概述

能力：`score`。

责任方：提供方平台维护者。

验证路径：

- 围绕上游 JEPA-WMS 打分接口添加一个精简适配器；
- 保持可选的 torch/检查点/运行时包由宿主方持有；
- 在调用运行时之前验证观测、目标和候选动作的张量形状；
- 验证有限打分输出、连贯的 `best_index` 和 JSON 原生元数据；
- 覆盖成功、格式错误的打分输出、运行时缺失和检查点缺失四条路径；
- 在已准备好的宿主上保留可选的实况冒烟清单。

推进理由：它在不新增媒体生成器或通用提供方名称的情况下，扩展了以 JEPA 为中心的规划路径。

### JEPA 公共适配器补充说明

决策日期：2026-05-01。

能力：`score`。

选定的上游：通过 `torch.hub.load("facebookresearch/jepa-wms", model_name)` 使用 [`facebookresearch/jepa-wms`](https://github.com/facebookresearch/jepa-wms)。

决策：将公共 `jepa` 目录条目从失败关闭的保留条目晋升为实验性仅打分适配器，复用 JEPA-WMS 运行时契约。该适配器需要 `JEPA_MODEL_NAME`，保持 PyTorch 和检查点由宿主方持有，且不暴露 `predict` 或 `embed`。

迁移说明：`JEPA_MODEL_PATH` 是旧的脚手架保留变量，仅作为无值诊断元数据保留；宿主方必须设置 `JEPA_MODEL_NAME` 以加载真实的上游模型。

为何不晋升所有 JEPA 接口：上游的动作条件 JEPA-WM 规划能够清晰地映射到候选动作打分。潜变量滚动和嵌入 API 需要在 WorldForge 声明 `predict` 或 `embed` 之前建立独立契约。

## 延期候选者

| 候选类别 | 延期原因 |
| --- | --- |
| 其他远程提供方 | 仅在具有明显不同的规划、预测、打分或策略工作流时才新增。 |
| 通用 LLM 问答提供方 | 世界状态问答在添加普通聊天/补全适配器之前，需要单独的类型化契约。 |
| 仿真器桥接 | 公共场景/状态边界和由宿主方持有的仿真器进程模型需要先有设计记录。 |
| LeRobot/GR00T 之外的新具身策略栈 | 机器人验证成本高；在新增更多策略运行时之前，应先完成策略符合性、转换器契约和已准备好宿主的证据。 |
| 主动推断或概率信念适配器 | 方向有价值，但 WorldForge 尚未具备类型化的信念/不确定性结果契约。 |
| 更多脚手架保留条目 | 依策略延期。没有可执行运行时契约的名称只会增加目录噪音。 |

## 非目标

- 不在本 RFC 中修改生成的提供方文档或提供方 README 页面。
- 不将提供方名称添加到自动注册中。
- 不将可选运行时包添加到基础依赖集中。
- 不在没有保留运行工件的情况下，将生成的视频、场景或策略作为物理保真度的证据。

## 后续规则

每个选定的提供方仍需单独的实现 PR。该 PR 必须说明：

- 能力接口和实现状态；
- 运行时归属权和可选依赖边界；
- 夹具和冒烟测试证据；
- 生成的文档行为；
- 脱敏和工件保留预期。

如果某个候选者无法满足上述要求，则将其保持延期状态并记录阻碍因素，而非添加脚手架。
